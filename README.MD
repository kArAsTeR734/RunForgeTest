# Runforge Runs

Тестовое задание Junior Frontend Developer: страница просмотра запусков AI-агентов.

## Текущий этап

Реализованы основные сценарии страницы Runs: список, совместный поиск и фильтрация,
подробности в модальном окне, загрузка, ошибка с повтором и пустой результат со сбросом условий.
Бонусы (сортировка, URL-фильтры, демо) пока не реализованы.

Уже есть:

- React + Vite + TypeScript в strict-режиме и CSS Modules.
- Модель `Run` из задания и 6 локальных запусков со всеми четырьмя статусами.
- Асинхронный mock-сервис: задержка 850 мс, управляемая ошибка, отмена через `AbortSignal`.
- Hook загрузки, список запусков, текстовые статусы, форматирование дат и длительности.
- Отдельный компонент поиска и фильтров перед списком: All, Queued, Running, Succeeded, Failed.
- Поиск по названию или репозиторию без учёта регистра, совместимый с фильтром статуса.
- Модальное окно с данными, логами и результатом; закрытие кнопкой или Escape и возврат фокуса к строке.
- Состояния загрузки и ошибки с повтором, пустой результат со сбросом поиска и фильтров.
- Базовая адаптивная вёрстка с молочным фоном и тёмно-синими элементами.
- Автотесты сервиса, хука и пользовательских сценариев страницы.
- ESLint с правилами TypeScript, React Hooks и React Refresh; Prettier с отступом в два пробела.

Требования и состояние реализации: [agents/REQUIREMENTS.MD](agents/REQUIREMENTS.MD).
Инструкции для разработки: [AGENTS.MD](AGENTS.MD) → [agents/AGENTS.MD](agents/AGENTS.MD).

## Стек

React 19, Vite 8, TypeScript 6, HTML, CSS Modules. Vitest и React Testing Library используются для тестов.
TypeScript 6.0.3 выбран для совместимости с `typescript-eslint` 8.72.1.
Версии установленных зависимостей фиксируются в `package-lock.json`.

## Установка и запуск

Нужны Node.js 22.13+ в ветке 22 либо Node.js 24+ и npm. Проект проверяется на Node.js 24.
Настройка Vite основана на [официальной инструкции](https://vite.dev/guide/).

Из корня проекта:

```bash
npm ci
npm run dev
```

Открой адрес, который Vite выведет в терминале (по умолчанию `http://localhost:5173`).
Если порт занят, Vite выберет следующий доступный. Переменные окружения не требуются.
В `.env.example` это явно отмечено: `import.meta.env.DEV` является встроенным флагом Vite,
автоматически заданным для dev-сервера и production-сборки. Копировать файл в `.env` для запуска не нужно.
Для изменения зависимостей используй `npm install`, затем сохраняй обновлённый lock-файл.

```bash
npm run typecheck  # Проверка TypeScript без генерации файлов
npm run lint       # Проверка ESLint
npm run lint:fix   # Автоматическое исправление поддерживаемых правил
npm run format     # Форматирование Prettier с отступом в два пробела
npm run format:check # Проверка форматирования без изменения файлов
npm test           # Однократный запуск тестов
npm run test:watch # Тесты в режиме наблюдения
npm run build      # Проверка типов и production-сборка в dist/
npm run preview    # Локальный просмотр production-сборки
```

## Структура проекта

Используется текущая структура проекта с папкой `entities`.

```text
agents/
  AGENTS.MD            Правила разработки для всего проекта
  REQUIREMENTS.MD      Требования, приоритеты и сценарии приёмки
src/
  app/                 Точка входа, App, глобальные стили и сборка приложения
  components/          Общие AppHeader и StatusBadge
  entities/
    run/               Типы Run, mock-данные, сервис запросов и его тесты
  features/
    runs/              RunsPage, RunsHeader, RunFilters, RunsContent,
                       RunList, RunDetailsModal и тесты страницы
  hooks/               React hooks (сейчас useRuns)
  utils/               Чистые функции, включая форматирование
AGENTS.MD              Переход к agents/AGENTS.MD
AI_LOG.md              Отчёт об использовании AI
README.MD              Инструкции по запуску и состоянию проекта
```

Компонентные стили размещаются рядом с компонентами в `*.module.css`.
Глобальные стили, базовые цвета и общий reset находятся в `src/app/global.css`.

`App` только собирает шапку и страницу. `RunsPage` управляет поиском, выбранным статусом и запуском.
`RunFilters` расположен перед `RunsContent`, который показывает загрузку, ошибку, пустой результат либо `RunList`.
Клик по любой строке открывает `RunDetailsModal`; закрытие сохраняет поиск и выбранный фильтр.
Модальное окно использует нативный `dialog.showModal()` для изоляции фокуса и блокировки фонового интерфейса.

## Запросы и состояние

`useRuns()` возвращает `data`, `error`, `status`, `isLoading`, `isSuccess`, `isError`, `reload`.
`status` принимает `loading`, `success` или `error`; флаги вычисляются из него, отдельно не хранятся.
`data` всегда имеет тип `Run[]`, `error` — `Error | null`. При начале запроса данные очищаются.
Это небольшой локальный hook без кэша и фонового обновления TanStack Query.

Внутри используется единое `runsQueryState`: связанные значения меняются согласованно.
`fetchRuns` сохраняет ссылку через `useCallback`, поскольку используется в зависимостях эффекта.
`reload` также имеет стабильную ссылку, переводит интерфейс в загрузку и запускает запрос.
Начальное состояние уже `loading`, поэтому первый запрос не вызывает лишнее синхронное обновление состояния из эффекта.

Каждый запрос отменяет предыдущий; очистка эффекта отменяет активный запрос при размонтировании.
При первом запуске активного запроса ещё нет и `activeRequest.current?.abort()` ничего не делает.
Отменённые ответы не обновляют UI. Mock-сервис возвращает Promise с задержкой 850 мс,
поддерживает явную ошибку и возвращает глубокую копию fixtures без приведения типов.

`void reload()` означает, что обработчик не использует возвращённый Promise.
Это не обработка ошибки: ошибки запроса перехватываются внутри хука.

## Проверки

Автотесты сервиса проверяют задержку, состав данных, независимость копий, ошибку с успешным повтором и отмену запроса.
Тесты хука проверяют переходы состояния, повтор после ошибки, отмену предыдущего запроса,
стабильность `reload`, отсутствие лишнего запроса при повторном рендере и очистку в StrictMode.
Тесты страницы проверяют все статусы, поиск по обоим полям, совместное применение условий,
сброс пустого результата, выбранные подробности с логами и результатом, отсутствие необязательных полей,
возврат фокуса и повтор после ошибки. Всего 19 тестов в трёх файлах.
В jsdom API диалога заменён тестовой реализацией; поведение настоящего модального окна проверено отдельно в браузере.

Ручная проверка:

1. Открой страницу: во время задержки видно сообщение загрузки, затем появляются 6 запусков.
2. Проверь четыре текстовых статуса, названия, репозитории, ветки, даты и длительности.
3. Проверь отсутствие длительности и значение `0 с`: оба случая отображаются корректно.
4. Выбери Running и введи `api-service`: останется Review API contracts. Очистка поиска сохраняет Running.
5. Введи отсутствующее имя и нажми «Сбросить поиск и фильтры»: вернутся все 6 запусков и All.
6. Открой Fix checkout tests: проверь репозиторий, ветку, дату, длительность, логи и результат. Закрой кнопкой и через Escape.
7. Открой Auth refactor и Add project settings: отсутствие результата/длительности и `0 с` обработаны корректно.
8. В dev-режиме вызови ошибку диагностической кнопкой, затем нажми «Повторить».
9. Проверь ширину 360 px и desktop, отсутствие ошибок в консоли, доступность кнопок с клавиатуры.

При разработке выполнен браузерный QA списка и модального окна на desktop и 360 px:
проверены совместная фильтрация, пустой результат, сброс, ошибка с повтором, Escape и возврат фокуса.
Сообщений error/warn в консоли проверенной страницы не обнаружено. Подробности проверок — в `AI_LOG.md`.
