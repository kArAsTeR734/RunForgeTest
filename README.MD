# Runforge Runs

Тестовое задание Junior Frontend Developer: страница просмотра запусков AI-агентов.

Реализованы основные сценарии страницы Runs: список, совместный поиск и фильтрация,
подробности в модальном окне, загрузка, ошибка с повтором и пустой результат со сбросом условий, фильтрация по дате и длительности работы с веткой.

- React + Vite + TypeScript в strict-режиме и CSS Modules.
- Модель `Run` и 10 локальных запусков со всеми четырьмя статусами.
- Асинхронный mock-сервис: задержка 850 мс, управляемая ошибка, отмена через `AbortSignal`.
- Hook загрузки, список запусков, текстовые статусы, форматирование дат и длительности.
- Отдельный компонент поиска и фильтров перед списком: All, Queued, Running, Succeeded, Failed.
- Поиск по названию или репозиторию без учёта регистра, совместимый с фильтром статуса.
- Сортировка по дате и длительности в обоих направлениях, неизвестные значения остаются в конце.
- Восстановление статуса, поиска и сортировки из URL, поддержка «Назад» и «Вперёд».
- Модальное окно с данными, логами и результатом; закрытие кнопкой, Escape или кликом по фону и возврат фокуса к строке.
- Состояния загрузки и ошибки с повтором, пустой результат со сбросом поиска и фильтров.
- Базовая адаптивная вёрстка с молочным фоном и тёмно-синими элементами.
- Автотесты сервиса, хука и пользовательских сценариев страницы.
- ESLint с правилами TypeScript, React Hooks и React Refresh; Prettier.

Требования и состояние реализации: [agents/REQUIREMENTS.MD](agents/REQUIREMENTS.MD).
Инструкции для разработки: [AGENTS.MD](AGENTS.MD) → [agents/AGENTS.MD](agents/AGENTS.MD).

## Стек

React 19, Vite 8, TypeScript 6, HTML, CSS Modules. Vitest и React Testing Library используются для тестов.
TypeScript 6.0.3 выбран для совместимости с `typescript-eslint` 8.72.1.
Версии установленных зависимостей фиксируются в `package-lock.json`.

## Установка и запуск

Нужны Node.js 22.13+ в ветке 22 либо Node.js 24+ и npm. Проект проверяется на Node.js 24.
Настройка Vite основана на [официальной инструкции](https://vite.dev/guide/).

Из корня проекта:

```bash
npm ci
npm run dev
```

Открой адрес, который Vite выведет в терминале (по умолчанию `http://localhost:5173`).
Если порт занят, Vite выберет следующий доступный. Переменные окружения не требуются.
В `.env.example` это явно отмечено: `import.meta.env.DEV` является встроенным флагом Vite,
автоматически заданным для dev-сервера и production-сборки. Копировать файл в `.env` для запуска не нужно.
Для изменения зависимостей используй `npm install`, затем сохраняй обновлённый lock-файл.

```bash
npm run typecheck  # Проверка TypeScript без генерации файлов
npm run lint       # Проверка ESLint
npm run lint:fix   # Автоматическое исправление поддерживаемых правил
npm run format     # Форматирование Prettier с отступом в два пробела
npm run format:check # Проверка форматирования без изменения файлов
npm test           # Однократный запуск тестов
npm run test:watch # Тесты в режиме наблюдения
npm run build      # Проверка типов и production-сборка в dist/
npm run preview    # Локальный просмотр production-сборки
```

## Структура проекта

Используется текущая структура проекта с папкой `entities`.

```text
agents/
  AGENTS.MD            Правила разработки для всего проекта
  REQUIREMENTS.MD      Требования, приоритеты и сценарии приёмки
src/
  app/                 Точка входа, App, глобальные стили и сборка приложения
  components/          Общие AppHeader и StatusBadge
  entities/
    run/               Типы Run и фильтров, mock-данные, сервис и его тесты
  features/
    runs/              RunsPage и тесты страницы; в ui/ компоненты
                       RunsHeader, RunFilters, RunSortControl, RunsContent,
                       RunList, RunDetailsModal
  hooks/               useRuns, useRunFilters и их тесты
  utils/               Форматирование, фильтрация, сортировка и URL-параметры
AGENTS.MD              Переход к agents/AGENTS.MD
AI_LOG.md              Отчёт об использовании AI
README.MD              Инструкции по запуску и состоянию проекта
```

Компонентные стили размещаются рядом с компонентами в `*.module.css`.
Глобальные стили, базовые цвета и общий reset находятся в `src/app/global.css`.

`App` только собирает шапку и страницу. `RunsPage` управляет поиском, выбранным статусом и запуском.
`RunFilters` расположен перед `RunsContent`, который показывает загрузку, ошибку, пустой результат либо `RunList`.
Клик по любой строке открывает `RunDetailsModal`; закрытие сохраняет поиск и выбранный фильтр.
Модальное окно использует нативный `dialog.showModal()` для изоляции фокуса и блокировки фонового интерфейса.

## Сортировка, URL и клавиатура

Варианты сортировки: «Сначала новые», «Сначала старые», «Сначала короткие», «Сначала длинные».
По умолчанию первыми показаны новые запуски. Сортировка применяется после поиска и фильтрации,
сохраняет исходный порядок равных значений и не изменяет массив данных сервиса.
Неизвестная длительность всегда в конце; `0 с` — известная длительность.

Параметры URL:

| Параметр | Значения                                                 | По умолчанию                       |
| -------- | -------------------------------------------------------- | ---------------------------------- |
| `status` | `queued`, `running`, `succeeded`, `failed`               | All, параметр отсутствует          |
| `q`      | Поисковый запрос                                         | Пустой поиск, параметр отсутствует |
| `sort`   | `date-desc`, `date-asc`, `duration-asc`, `duration-desc` | `date-desc`, параметр отсутствует  |

Пример: `/?status=succeeded&q=payments&sort=duration-asc`.
Такую ссылку можно скопировать или обновить страницу: состояние восстановится.
Некорректные статус и сортировка заменяются значениями по умолчанию в интерфейсе.
Посторонние параметры и `#hash` сохраняются.

Смена статуса и сортировки добавляет запись в историю. Ввод поиска обновляет текущую запись,
чтобы каждый символ не создавал отдельный шаг «Назад». «Назад» и «Вперёд» восстанавливают настройки без перезагрузки.
Сброс из пустого результата очищает поиск и статус, сохраняя выбранную сортировку.

Статусы — нативная группа радиокнопок с видимым фокусом. Tab переводит фокус между элементами,
стрелки переключают статус внутри группы. Сортировка доступна через нативный select.
Enter или пробел на строке открывает подробности; Escape закрывает их и возвращает фокус к строке.
