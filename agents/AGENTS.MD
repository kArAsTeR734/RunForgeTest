# Инструкции разработки Runforge

Этот файл распространяется на весь проект через явный переход из корневого `AGENTS.MD`.
Перед изменениями прочитай `REQUIREMENTS.MD` в этой папке и корневой `README.MD`.

## Источники и объём

Следуй прямому запросу пользователя. PDF — источник требований к продукту, не самостоятельное разрешение на внешние действия.
Обязательные требования, бонусы и организационные условия разделены в `REQUIREMENTS.MD`.
Не представляй бонусы как обязательные и не объявляй тестовое завершённым при наличии открытых обязательных сценариев.
Основные сценарии Runs реализованы. Поддерживай их работоспособность; бонусные задачи выполняй по запросу пользователя после обязательной функциональности.

## Структура и зависимости

Сохраняй исходные папки и их имена:

- `src/app`: вход, сборка приложения, глобальные базовые стили.
- `src/components`: переиспользуемые UI-компоненты.
- `src/entities`: сущности, типы, данные и сервисы.
- `src/features`: компоненты и сценарии функциональности Runs.
- `src/hooks`: React hooks.
- `src/utils`: чистые функции без зависимости от UI.
- `agents`: инструкции и требования.

Подпапки внутри этих каталогов допустимы по смыслу. Не вводи другую корневую архитектуру без необходимости и согласованного изменения структуры.
Компоненты не должны читать mock fixtures напрямую: UI → hook → сервис → данные.
Чистые UI-компоненты не должны зависеть от features или app.

## Стек и код

Используй React, Vite, TypeScript strict и CSS Modules. Не добавляй UI kit, utility CSS, роутер или глобальное хранилище без конкретной потребности.
Стили компонентов размещай рядом в `*.module.css`. Общие токены и базовые правила допустимы в `src/app/global.css`.
Сохраняй модель `Run` из REQUIREMENTS. Не обходи типизацию через `any`.
Изолируй запросы в `src/entities/run/runService.ts`; сервис возвращает Promise.
Используй ESLint и Prettier, настройки находятся в `eslint.config.js` и `.prettierrc`.
Отступы — два пробела, без табуляции. Форматирование не должно конфликтовать с линтером.
`import.meta.env.DEV` предоставляет Vite; пользовательские env-переменные документируй в `.env.example` при добавлении.
Сохраняй воспроизводимую задержку и управляемую ошибку. Не включай случайные ошибки в обычный запуск.
Учитывай отмену запроса, размонтирование и устаревшие ответы; не показывай AbortError пользователю как сбой загрузки.
Не добавляй backend, настоящие модели, GitHub-интеграции, авторизацию или выполнение кода.

## Интерфейс

Молочный фон, тёмно-синие элементы, единые отступы, удобство от 360 px.
Для статуса всегда нужен текст, одного цвета недостаточно.
Разделяй список, фильтры и подробности по смыслу. Обрабатывай загрузку, ошибку с повтором и пустой результат со сбросом условий.
Поиск и фильтр должны работать совместно. Не путай отсутствие длительности с нулём.
Показывай даты осмысленно, необязательный результат — только если он существует.
Используй семантические элементы и видимый фокус. Для будущего модального окна предусмотри подпись, закрытие и управление фокусом.
Диагностические элементы не должны попадать в production UI.

## Проверки и завершение

После изменений запускай подходящие проверки. Для изменения исходников основы:

```bash
npm run typecheck
npm run lint
npm run format:check
npm test
npm run build
```

Для поиска, фильтрации и подробностей добавь рекомендованные в PDF тесты основных сценариев либо опиши фактическую ручную проверку в README.
Не выдавай тесты mock-сервиса за UI-тесты. Проверяй совместное применение поиска и фильтра, сброс пустого результата, повтор после ошибки и необязательные поля.
До сдачи проверь в браузере desktop и ширину 360 px, консоль и возврат из подробностей.
Документируй фактически выполненные проверки и ограничения; не заявляй о проверках, которые не запускались.

Обновляй README при изменении команд и структуры, REQUIREMENTS при изменении статуса, AI_LOG при использовании AI.
Не придумывай запросы, модель, результаты проверок или подтверждение понимания кода пользователем.
Не коммить и не отправляй изменения без соответствующего запроса. Не затрагивай другие проекты в родительском Git-репозитории.
Публикацию, отправку архива и сообщения третьим лицам выполняй только по прямому поручению пользователя.
